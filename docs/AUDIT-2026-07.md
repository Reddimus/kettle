# Reliability and tracked-tree audit - 2026-07-09

This audit covers the native Windows incidents reported during Codex/Claude
development, the supplied screen recording, GPU recovery, terminal selection,
and every Git-tracked repository path. Claims below distinguish reproduced
causes from historical inferences.

## Incident findings

### Codex cursor at the lower left

All 260 decoded frames of `Screen Recording 2026-07-09 150019.mp4` were reviewed
alongside the corresponding terminal cells. The bright block is Kettle's normal
DEC cursor drawn over Codex CLI's dim `Explain this codebase` composer
placeholder while Codex is active. A scrubbed ConPTY fixture reproduces the two
observed PTY reads: the transient status position followed by the active
composer position.

The fix is structural and allocation-free. On native Windows only, Kettle
recognizes an active Codex footer and suppresses transient status/model cursors
plus a composer cursor whose cell is dim. It does not alter parsed terminal
state. A non-dim queued-input caret, an idle Codex prompt, ordinary shells, and
Linux/WSL cursors remain visible.

### Text apparently left from an earlier chat

The observed lower section is the same active-placeholder sequence, not retained
cells from another Kettle pane or process. The live regression now asserts both
states at cell and pixel level: the empty placeholder has zero bright cursor
pixels while queued input retains a visible caret. Separately, omitted DEC 2026
synchronized-update terminators now have behavioral timeout tests, so an
interrupted TUI frame is force-flushed at the parser deadline rather than being
left indefinitely pending.

### Startup and GPU failures

Two historical crash logs prove a distinct startup panic: code subtracted 60
seconds from a monotonic `Instant` less than 60 seconds after Windows boot. This
was misattributed to GPU discovery because it occurred during startup. Trigger
and remote-poll clocks now represent `never fired` with `Option<Instant>` and
use saturating elapsed-time comparisons.

The exact trigger for the separate historical GPU-unavailable event is not
recoverable because the old build recorded no adapter fault or recovery stage.
The machine currently enumerates an NVIDIA GeForce RTX 2080 over Vulkan (driver
591.86, PCI `10de:1e87`). RDP/session transitions or a wgpu device loss remain
the evidence-supported explanations, but are inferences rather than a proven
root cause.

Fatal wgpu errors now latch the first bounded reason without doing callback-thread
I/O. The event loop atomically rebuilds every live window through the configured
adapter, alternate hardware, then software rendering while PTYs remain alive.
Fault-only JSONL diagnostics are capped at 256 KiB, rotated to ten incidents,
and exclude terminal text, commands, cwd, and environment data.

The software path was exercised on this machine without inducing a TDR:

- `--gpu-info` selected Microsoft Basic Render Driver (`Dx12`, CPU,
  `1414:008c`) under `gpu-force-software = true`.
- A real software-backed 800x600 Kettle window accepted input over its PTY,
  returned a control-server marker, and produced a nonblank 727-color capture.
- The renderer log explicitly recorded `requesting the software adapter`.

The active machine config was backed up as
`config.backup-20260709-175107`; its stale NVIDIA vendor/device/name pin was
removed, while `gpu-power-preference = auto` was retained. Config validation is
clean and automatic selection still resolves the RTX 2080 on the current
session, without preventing fallback after an adapter/session change.

## Repository audit

`scripts/audit-tracked-files.py` walks every stage-0 entry from
`git ls-files --stage` and emits a per-file JSON ledger. It verifies:

- canonical, non-escaping paths and case-fold uniqueness;
- index object IDs, worktree object IDs, and SHA-256 digests;
- UTF-8, LF-only text, final newlines, and trailing whitespace policy;
- TOML/JSON parsing and local Markdown link targets;
- SFNT font table bounds/required tables and PNG chunk bounds/CRCs.

The first pass covered all 744 then-tracked files (16,074,767 bytes). It found
four pre-existing asset-hygiene defects: trailing spaces in two theme-license
copies and the font license, plus a missing final newline in `hazyland`. After
those fixes the same pass reported zero errors and zero warnings. The final
staged release audit includes the new diagnostics, audit script, and this report;
it covers 747/747 files (16,121,106 bytes) with zero dirty objects, errors, or
warnings. Its machine-readable output lives under ignored
`target/diagnostics/tracked-files-audit.json`.

## Architectural follow-up

This release keeps behavior changes independently testable: cursor policy,
monotonic throttles, GPU recovery state, GPU incident serialization, resize
classification, PTY queueing, and control-protocol caps all have pure or focused
tests. The large `app.rs` decomposition and other intentionally structural work
remain tracked in [AUDIT-DEFERRED.md](AUDIT-DEFERRED.md); moving 20,000 lines
during an incident release would increase risk without changing the verified
behavior above.
